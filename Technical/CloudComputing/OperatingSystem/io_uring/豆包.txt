## 一、io_uring 核心认知
### 1. 什么是 io_uring？
io_uring 是 Linux 内核 5.1 版本引入的**异步 I/O 框架**，旨在解决传统异步 I/O（libaio）的局限性（如仅支持块设备、接口不友好、性能开销高），提供一套统一、高效、易用的异步 I/O 接口，目前已成为高性能网络/存储编程的主流选择。

### 2. 核心优势（对比传统 I/O 模型）
| 传统模型（epoll/select/libaio） | io_uring |
|---------------------------------|----------|
| 频繁系统调用（如 epoll_ctl/epoll_wait） | 极少系统调用，核心逻辑通过共享内存完成 |
| 部分模型有内存拷贝开销          | 减少内核-用户态内存拷贝 |
| libaio 仅支持块设备             | 支持文件、网络、管道等几乎所有 I/O 类型 |
| 接口设计复杂                    | 接口简洁，支持链式请求、超时、取消等高级特性 |

### 3. 核心组件
io_uring 的核心是**两个共享内存环形队列**（用户态和内核态直接共享，无拷贝）：
- **SQ（Submission Queue）**：提交队列，用户态向内核提交 I/O 请求（如读文件、写 socket）的队列。
  - 每个元素是 `SQE`（Submission Queue Entry）：对应一个具体的 I/O 请求（如读操作、写操作）。
- **CQ（Completion Queue）**：完成队列，内核将已完成的 I/O 请求结果（成功/失败、字节数）通知用户态的队列。
  - 每个元素是 `CQE`（Completion Queue Entry）：对应一个完成的 I/O 请求结果。
- 辅助系统调用：
  - `io_uring_setup()`：创建 io_uring 实例，初始化 SQ/CQ 环。
  - `io_uring_enter()`：触发内核处理 SQ 中的请求，或等待 CQ 中的完成事件。
  - `io_uring_register()`：注册文件/缓冲区，进一步提升性能（减少重复校验开销）。

## 二、io_uring 基本使用流程
io_uring 的使用遵循「创建实例 → 填充请求 → 提交请求 → 处理结果」的核心流程，以下是简化的步骤：
1. 调用 `io_uring_setup()` 创建 io_uring 实例，指定队列大小，获取内核返回的文件描述符和共享内存信息。
2. 映射 SQ/CQ 环到用户态内存（通过 `mmap`），方便直接操作。
3. 从 SQ 中获取空闲的 `SQE`，填充 I/O 操作类型（如 `IORING_OP_READ`）、文件描述符、缓冲区、偏移量等参数。
4. 调用 `io_uring_enter()` 通知内核处理 SQ 中的请求。
5. 轮询/等待 CQ 中的 `CQE`，解析 I/O 操作结果（成功/失败、处理的字节数）。
6. 释放资源（关闭 io_uring 文件描述符、解除内存映射）。

## 三、实际代码示例（文件异步读取）
为了让你快速上手，这里提供一个基于 `liburing`（官方封装库，简化原生系统调用使用）的完整示例，实现文件的异步读取。

### 前置条件
- 内核版本 ≥ 5.1（建议 5.8+，功能更完善）。
- 安装 liburing 开发库：
  ```bash
  # Ubuntu/Debian
  sudo apt install liburing-dev
  # CentOS/RHEL
  sudo dnf install liburing-devel
  ```

### 完整代码
```c
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>
#include <liburing.h>

#define QUEUE_DEPTH 16  // 队列深度（SQ/CQ 大小）
#define BUF_SIZE    4096 // 读取缓冲区大小

int main(int argc, char *argv[]) {
    if (argc != 2) {
        fprintf(stderr, "用法: %s <文件名>\n", argv[0]);
        exit(EXIT_FAILURE);
    }

    // 1. 初始化 io_uring 实例
    struct io_uring ring;
    int ret = io_uring_queue_init(QUEUE_DEPTH, &ring, 0);
    if (ret < 0) {
        perror("io_uring_queue_init 失败");
        exit(EXIT_FAILURE);
    }

    // 2. 打开文件（只读模式）
    int fd = open(argv[1], O_RDONLY);
    if (fd < 0) {
        perror("open 失败");
        io_uring_queue_exit(&ring);
        exit(EXIT_FAILURE);
    }

    // 3. 分配读取缓冲区
    char *buf = malloc(BUF_SIZE);
    if (!buf) {
        perror("malloc 失败");
        close(fd);
        io_uring_queue_exit(&ring);
        exit(EXIT_FAILURE);
    }

    // 4. 获取空闲 SQE 并填充读取请求
    struct io_uring_sqe *sqe = io_uring_get_sqe(&ring);
    if (!sqe) {
        perror("io_uring_get_sqe 失败");
        free(buf);
        close(fd);
        io_uring_queue_exit(&ring);
        exit(EXIT_FAILURE);
    }
    // 填充 SQE：操作类型（读）、文件描述符、缓冲区、长度、偏移量
    io_uring_prep_read(sqe, fd, buf, BUF_SIZE, 0);
    // 绑定用户数据（方便后续关联请求和结果）
    io_uring_sqe_set_data(sqe, buf);

    // 5. 提交请求到内核
    ret = io_uring_submit(&ring);
    if (ret <= 0) {
        perror("io_uring_submit 失败");
        free(buf);
        close(fd);
        io_uring_queue_exit(&ring);
        exit(EXIT_FAILURE);
    }

    // 6. 等待并处理 CQE（完成事件）
    struct io_uring_cqe *cqe;
    ret = io_uring_wait_cqe(&ring, &cqe);
    if (ret < 0) {
        perror("io_uring_wait_cqe 失败");
        free(buf);
        close(fd);
        io_uring_queue_exit(&ring);
        exit(EXIT_FAILURE);
    }

    // 解析完成结果
    if (cqe->res < 0) {
        fprintf(stderr, "读取失败: %s\n", strerror(-cqe->res));
    } else {
        printf("成功读取 %d 字节，内容前 100 字节：\n", cqe->res);
        fwrite(buf, 1, cqe->res > 100 ? 100 : cqe->res, stdout);
        printf("\n");
    }

    // 7. 标记 CQE 已处理（释放队列空间）
    io_uring_cqe_seen(&ring, cqe);

    // 8. 释放资源
    free(buf);
    close(fd);
    io_uring_queue_exit(&ring);

    return EXIT_SUCCESS;
}
```

### 编译与运行
```bash
# 编译（链接 liburing 库）
gcc -o io_uring_demo io_uring_demo.c -luring
# 运行
./io_uring_demo test.txt
```

### 代码关键解释
- `io_uring_queue_init()`：封装了 `io_uring_setup()` 和 `mmap`，简化实例创建。
- `io_uring_get_sqe()`：从 SQ 中获取空闲的请求项，是提交请求的前提。
- `io_uring_prep_read()`：填充读请求的核心参数（操作类型、fd、缓冲区等）。
- `io_uring_submit()`：提交 SQ 中的请求到内核，触发 I/O 操作。
- `io_uring_wait_cqe()`：阻塞等待 CQ 中的完成事件，也可使用非阻塞方式（`io_uring_peek_cqe()`）。
- `io_uring_cqe_seen()`：通知内核该 CQE 已处理，释放队列空间。

## 四、进阶研究方向
如果想深入研究，可重点关注以下方向：
1. **高性能配置**：
   - `SQPOLL`：内核创建线程轮询 SQ，彻底消除 `io_uring_enter()` 系统调用开销。
   - `IOPOLL`：I/O 轮询模式，避免中断开销（适合高性能存储场景）。
2. **高级特性**：
   - 链式请求（`IORING_OP_LINK`）：多个请求按顺序执行，前一个完成后自动触发下一个。
   - 请求超时（`io_uring_prep_timeout()`）：为 I/O 请求设置超时时间。
   - 请求取消（`io_uring_prep_cancel()`）：取消未完成的 I/O 请求。
3. **应用场景**：
   - 高性能 Web 服务器（如 Nginx 已支持 io_uring）。
   - 数据库存储引擎（如 PostgreSQL、MySQL 都在适配 io_uring）。
   - 分布式存储系统（如 Ceph、MinIO）。

### 总结
1. **核心定位**：io_uring 是 Linux 下新一代异步 I/O 框架，核心优势是低系统调用开销、高通用性、高性能。
2. **核心组件**：基于 SQ（提交队列）和 CQ（完成队列）两个共享内存环，通过 `SQE` 提交请求、`CQE` 获取结果。
3. **使用关键**：实际开发中优先使用 `liburing` 库（简化原生系统调用），核心流程是「创建实例 → 填充 SQE → 提交 → 处理 CQE」。
